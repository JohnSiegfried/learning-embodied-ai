# 1.2 机器人系统解剖

## 一句话

机器人 = **本体**（结构骨架）+ **传感器**（感知入口）+ **执行器**（动作出口）+ **控制器**（把"想动"翻译成"电机转多少"的实时翻译官）——而软件背景的学习者可以在仿真里把这四层的**功能**全部学到手，最后才需要碰真铁。

## 核心原理

### 1. 四层解剖与数据流（把 1.1 的闭环落到硬件上）

```
   [传感器]                [控制器/计算机]              [执行器]
   相机 ──图像──┐          ┌── 策略网络(GPU, ~30Hz)     ──┐
   编码器─关节角─┼─数据总线─┤                             ├─电流指令─→ 电机转动
   IMU ──姿态──┘          └── 实时控制器(MCU, ~1kHz)  ───┘         │
                                                                    ▼
                                                              本体(连杆+关节)运动
                                                                    │
                                                          改变了世界和自己的姿态 ──→ 传感器又看到新数据（闭环！）
```

四层各自回答一个问题：

| 层 | 回答的问题 | 硬件实例 | 软件人对应物 |
|---|---|---|---|
| 本体 Body | 力从哪里传到哪里？ | 连杆、关节、减速器、夹爪 | 模型结构（architecture） |
| 传感器 Sensor | 世界和自身状态是什么？ | 相机、深度相机、关节编码器、IMU、触觉阵列 | 输入管道（tokenizer 的物理版） |
| 执行器 Actuator | 怎么产生力？ | 电机（有刷/无刷/舵机）、谐波减速器、准直驱电机 | 输出层（logits 的物理版） |
| 控制器 Controller | 想法怎么变成电流？ | 板载实时 MCU（1kHz 循环）+ 上位机（跑策略） | 推理引擎 + runtime |

### 2. 关节与自由度（本体的语法）

- **关节两种基本类型**：转动关节（revolute，绝大多数）与移动关节（prismatic，如直线滑轨）
- **自由度（DOF, Degree of Freedom）**：独立可控制运动的方向数。你的手臂 ≈ 7 DOF（肩 3 + 肘 1 + 腕 3），常见桌面机械臂 6 DOF，人形机器人全身 20–40+ DOF
- **位姿 6 维 vs 关节 N 维**：手爪在空间中的位姿（位置 x,y,z + 朝向 3 维）只要 6 个数；但关节角有 N 个数。**当 N > 6（如 7 DOF 臂），同一目标位姿有无穷多种关节姿态可实现**——这个"冗余"正是传统方法头疼、学习方法发光的地方（伏笔 → 1.3 逆运动学、Phase 2 学习策略）

### 3. 执行器：为什么电机后面总挂个"减速器"

- 电机天然**快而弱**（转速上万 RPM、力矩小），机器人需要**慢而强**（几十 RPM、大力矩）→ 谐波减速器把速度换力矩
- 代价：间隙（backlash）与弹性 → 控制变难。**准直驱（quasi-direct-drive）**路线（MIT Cheetah、宇树）用大扭矩低转速电机省掉减速器，换取更好的力控——这是当前人形机器人的主流选择
- 力矩控制 vs 位置控制：告诉电机"转 90°"（位置控制）vs"用 2 N·m 的力"（力矩控制）——力控是柔顺操作（倒水、擦桌子）的前提（伏笔 → 4.4 阻抗控制）

### 4. 传感器：本体感知 vs 外部感知

- **本体感知（Proprioception）**：关节编码器（每个关节角多少度）、IMU（自身姿态/加速度）——"闭着眼知道自己的手在哪"
- **外部感知（Exteroception）**：RGB 相机、深度相机、激光雷达、触觉传感器——"看见世界"
- 当前 VLA 时代的主流配置极其朴素：**几个相机 + 关节编码器**，这就够了（Phase 3 你会看到 OpenVLA 的输入就是图像 + 语言指令）

### 5. 为什么仿真可以顶替硬件（本课程能"零硬件"的原因）

仿真器（PyBullet/MuJoCo/Isaac Lab）= **物理引擎**：用数值方法解算重力、摩擦、碰撞、关节动力学。它给你：

- 完美的传感器数据（无噪声的相机图、精确的关节角）
- 完美的虚拟执行器（指令即执行、无延迟）
- 廉价、可并行、可试错（摔一万次也不心疼）

真实世界的三宗罪——**噪声、延迟、损坏**——正是 Sim2Real gap 的来源（Phase 4 主菜）。学习路径：先在仿真里把方法跑通，再花最小代价迁移。

### 6. 本课最小公式集（必须掌握）

1. **关节空间 vs 任务空间**（本课最重要的一对定义）：
   - 关节空间坐标：$q = [q_1, \dots, q_N] \in \mathbb{R}^N$（N 个关节角，电机真正接受的量）
   - 任务空间位姿：$x \in SE(3)$（位置 3 维 + 朝向 3 维 = 6 维，人类下达任务的量）
   - 关系：$x = FK(q)$（正运动学，唯一解）；$q = IK(x)$（逆运动学，可能多解/无解）。**下一课全部在讲这两个函数。**
2. **电机力矩方程**：$\tau_m = K_t \cdot i$（$K_t$：力矩常数，$i$：电流）——力控的本质是控电流
3. **减速器换算**：$\tau_{out} = N \cdot \tau_m \cdot \eta,\quad \omega_{out} = \omega_m / N$（$N$：减速比，$\eta$：传动效率）
4. **实时控制约束**：1 kHz 控制环意味着每 1 ms 内必须完成"读传感 → 算出 → 写电流"整个循环——这就是为什么快层容不下大模型

### 7. 代码预览：读取"本体感知"（PyBullet，exp01 前菜）

```python
import pybullet as p
import pybullet_data

p.connect(p.DIRECT)  # 无界面模式；调试时可换 p.GUI
p.setAdditionalSearchPath(pybullet_data.getDataPath())
robot = p.loadURDF("kuka_iiwa/model.urdf")   # 7-DOF KUKA 机械臂

n = p.getNumJoints(robot)
for j in range(n):
    angle, vel, _, _ = p.getJointState(robot, j)  # ← 这就是本体感知
    print(f"joint {j}: angle={angle:.2f} rad, vel={vel:.2f} rad/s")
```

跑通这段 = 你已经拿到了机械臂的"关节编码器"数据，它就是后面所有策略网络的输入之一。

- **讲评**：不知道很正常——这正是 1.3 的主题。答案预告：换算叫**运动学（Kinematics）**，需要三类输入：
  1. **结构几何**：每节连杆多长、关节轴朝哪（机械臂出厂时已知）
  2. **当前关节角**：编码器实时读数（本课讲的"本体感知"）
  3. **坐标系定义**：基座在哪、目标"往左"是相对谁说的
